# M1 - Fast-forward vs --no-ff  (Easy)

`seed/m1-feature` is two commits ahead of `seed/m1-main` and nothing else has
happened, so a merge here can go two different ways. Produce both:

- `answer/m1-ff`   - branch from `seed/m1-main`, integrate `seed/m1-feature`
                     as a **fast-forward**. The result must have NO merge
                     commit and must be identical to the feature tip.
- `answer/m1-noff` - branch from `seed/m1-main`, integrate `seed/m1-feature`
                     forcing a **merge commit**, whose message must be
                     exactly `Merge feature: search`.

In SOLUTIONS.md, give the flag that guarantees each outcome and name one
concrete situation where a team would insist on `--no-ff`.
