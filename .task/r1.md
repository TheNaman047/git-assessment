# R1 - Look before you leap: fetch, not pull  (Easy)

`seed/r1-upstream` stands in for "the remote has moved on". `seed/r1-local`
is where you are.

Without merging, rebasing or resetting anything into your branch, work out
what upstream has that you do not, and write it down.

On `answer/r1` (branched from `seed/r1-local`), add exactly ONE commit that
creates `REPORT.md` with this exact shape - one line per incoming commit,
oldest first, subject only:

    # Incoming from upstream
    - <subject of oldest incoming commit>
    - <subject of next>
    - <subject of newest>

Commit message: `docs: record incoming upstream commits`

`answer/r1` must contain NONE of the upstream commits. In SOLUTIONS.md,
state the one command you used to list them and explain why `git pull`
would have been the wrong tool here.
