# S1 / S2 - Splitting a monorepo  (Medium / Hard)

`seed/split` adds a `plugins/` tree and a `tools/` tree on top of `main`.
Both tasks below start from a **fresh clone** of your fork - `git filter-repo`
refuses to run on a clone that already has your work in it, and it is
destructive, so never run it in your main working copy.

## S1 (Medium) - one directory becomes the repo root

Extract `plugins/slack/` into a new public GitHub repo called
`taskflow-slack`, keeping its history. In the new repo, `index.js` and
`format.js` must sit at the **root** (no `plugins/slack/` prefix), and the
history must contain only the commits that touched those files.

## S2 (Hard) - several paths, prefix preserved

Extract the whole `plugins/` tree into a new public GitHub repo called
`taskflow-plugins`, keeping the `plugins/` prefix and the history of every
file under it - but leaving `tools/` behind entirely.

For both: record the new repository URLs and the exact `git filter-repo`
invocation in SOLUTIONS.md, and explain the difference between
`--subdirectory-filter` and `--path`, and why filter-repo insists on a fresh
clone.
